# Overline MVP 실기기 테스트 런북

이 문서는 Overline MVP가 "예쁘게 보이는 목업"을 넘어 실제 iPhone에서 종이책 캡처, 저장, 책 검색, 인사이트 생성까지 동작하는지 판정하기 위한 실행 절차다. 최종 증거는 앱 안의 `책장 > MVP 점검 > 검증 리포트`, `테스트 세션 기록`, 그리고 복사한 현장 체크리스트로 남긴다.

## 통과 기준

MVP 통과는 아래 10개 항목이 모두 실제 기기에서 확인되고, 최신 실제 iPhone 테스트 세션에 `실패/재검증 필요`와 `미확인` 항목이 없을 때로 본다. 앱의 `기능 점검 10/10`은 체크리스트가 모두 채워졌다는 뜻이고, 최종 통과는 `MVP 통과 가능`으로 표시되어야 한다.

| 항목 | 통과 조건 | 앱 안의 증거 |
| --- | --- | --- |
| 10초 안에 캡처 저장 | 앱 진입 후 카메라 캡처 저장까지 10초 이하 | 검증 리포트의 캡처 성능, MVP 점검 |
| 캡처 경로 3탭 이하 | 열기, 선 긋기, 저장 흐름이 끊기지 않음 | MVP 점검 |
| 한국어 OCR 90% 이상 | 실제 한국어 책 문장 기준 수정 필요 줄 수가 10% 이하 | OCR 검증 기록 |
| 페이지 경계 감지 | 책 페이지 윤곽이 화면의 실제 페이지를 따라옴 | MVP 점검 |
| 캡처 스냅샷 저장 | 글조각 상세에서 선택 영역 스냅샷 확인 | 책 상세, 검증 리포트 |
| 저조도 캡처 | 어두운 환경에서 안내와 플래시 토글 후 저장 가능 | MVP 점검 |
| ISBN 스캔 | 실제 책 바코드를 카메라로 읽어 책 검색 실행 | MVP 점검 |
| 음성 메모 | 온디바이스 STT로 메모 텍스트 저장 | MVP 점검 |
| 도서 API | Kakao 또는 Aladin 도서 검색 성공 | 책 추가, 검증 리포트의 `도서 API` |
| LLM 인사이트 | API 키와 모델로 현재 모델 테스트 또는 인사이트 생성 성공 | 인사이트 탭, 검증 리포트의 `LLM 연결` |

## 준비물

- 실제 iPhone 1대. 시뮬레이터는 UI 빌드 확인용이며 MVP 통과 증거가 아니다. 앱의 검증 리포트에서도 시뮬레이터 세션은 `빌드 확인용`으로 표시된다.
- 앱 설치본. Xcode 직접 설치 또는 TestFlight 빌드 모두 가능하다.
- 한국어 종이책 1권. ISBN 바코드가 보이는 뒷표지가 있으면 좋다.
- Kakao REST API 키와 Aladin TTBKey가 `Config/Secrets.xcconfig`에 준비되어 있어야 한다.
  - 도서 API 키가 앱 번들에 포함되는 방식과 검증 절차는 [BOOK_METADATA_API_KEYS.md](BOOK_METADATA_API_KEYS.md)를 따른다.
- LLM 제공자 API 키 또는 구독 토큰 1개 이상. 인사이트 생성은 OpenRouter, Anthropic, OpenAI, Gemini 중 하나로 시작하면 된다. 자동 태그 보강은 Anthropic, OpenAI, Gemini 설정이 있을 때 동작한다.
- 조명을 낮출 수 있는 환경. 저조도와 플래시 토글을 확인하기 위함이다.

## 사전 점검

1. 앱을 실행하고 카메라, 마이크, 음성 인식 권한을 허용한다.
2. `책장 > MVP 점검 > 검증 리포트`를 열어 프리플라이트를 확인한다.
3. 프리플라이트에서 카메라, 마이크, 음성 인식 권한 외에 `도서 API 키 준비`, `LLM API 키 준비`, `주 저장소`, `백업 저장`, `스냅샷 정책`, `개인정보 매니페스트`, `권한 문구`, `App Intents`, `번들 ID`, `앱 버전`, `앱 아이콘`, `API 키 보관`이 준비 상태인지 확인한다.
4. `책장 > MVP 점검 > 실제 기기 테스트 절차`에서 우상단 복사 버튼으로 현장 체크리스트를 복사해 둔다.
5. `책 추가`에서 ISBN 또는 제목으로 도서를 검색한다.
6. `인사이트 > AI 설정`에서 사용할 제공자, 모델, API 키 또는 구독 토큰을 입력한다.
7. `현재 모델 테스트`를 눌러 최소 1회 성공 응답을 확인한다.

주의: 검증 리포트에는 API 키와 원문 전체가 포함되지 않아야 한다. 공유할 때도 캡처 문장 전문을 공개 채널에 올리지 않는다.

## 앱 상태 문구 해석

| 앱 문구 | 의미 | 다음 행동 |
| --- | --- | --- |
| 기능 점검 진행 중 | 10개 MVP 체크리스트 중 아직 남은 항목이 있음 | `검증 리포트 > 다음 조치`를 따라 남은 항목 확인 |
| 기능 점검 10/10 | 체크리스트는 모두 채워졌지만 최신 실제 iPhone 통과 세션은 아직 없음 | `테스트 세션 기록`에서 실제 iPhone 세션 저장 |
| MVP 통과 가능 | 체크리스트 10/10과 최신 실제 iPhone 세션이 모두 통과 | 검증 리포트 복사 후 증거로 보관 |
| 빌드 확인용 | 시뮬레이터 세션이거나 실기기 증거가 아님 | 실제 iPhone에서 다시 테스트 |
| 도서 API 키 준비 / LLM API 키 준비 | API 키가 포함되어 프리플라이트 준비는 됨 | 실제 검색과 연결 테스트를 성공시켜 `도서 API`, `LLM 연결`을 남김 |

## 테스트 절차

### 1. 캡처 흐름

1. 캡처 탭을 열고 실제 책 페이지를 화면에 맞춘다.
2. 페이지 윤곽선이 실제 종이 페이지를 따라오는지 본다.
3. 마음에 드는 문장 위를 손가락으로 가로로 긋는다.
4. 메모 없이 저장하거나 짧은 메모를 입력해 저장한다.
5. 저장 상태에 10초 이하 시간이 표시되는지 확인한다.
6. 책장 상세에서 글조각 텍스트와 스냅샷이 함께 저장됐는지 확인한다.
7. 책 기본 태그가 붙고, 같은 책에서 2회 이상 반복된 태그가 다음 캡처의 기본 후보로 재사용되는지 확인한다.

통과하면 MVP 점검의 `10초 안에 캡처 저장`, `캡처 경로 3탭 이하`, `페이지 경계 감지`, `캡처 스냅샷 저장`을 체크한다.

### 2. OCR 정확도

1. 같은 책에서 한국어 문장 여러 줄을 캡처한다.
2. 글조각 편집 화면에서 원문과 OCR 결과를 대조한다.
3. `책장 > OCR 검증 기록`에 검증 책 또는 샘플명, `실제 한국어 책`, 검증한 줄 수, 수정 필요 줄 수를 입력한다.
4. 정확도 90% 이상과 실제 한국어 책 근거가 함께 있어야 M0 통과로 기록되는지 확인한다.

### 3. 저조도

1. 조명을 낮추고 같은 페이지를 비춘다.
2. 저조도 안내 또는 플래시 토글 상태를 확인한다.
3. 플래시를 켜거나 자동 상태에서 문장을 캡처하고 저장한다.
4. 저장된 글조각이 읽을 수 있는 품질인지 확인한다.

통과하면 MVP 점검의 `저조도 캡처`를 체크한다.

### 4. 책 정보

1. `책 추가`에서 ISBN 스캔을 연다.
2. 실제 책 뒷표지의 바코드를 카메라로 읽는다.
3. Kakao 검색 결과로 제목, 저자, 책소개, 표지 URL이 채워지는지 확인한다.
4. Kakao 결과가 없으면 Aladin fallback 또는 수동 입력이 가능한지 확인한다.
5. 책 상세 하단에 `도서 DB 제공: 카카오` 또는 `도서 DB 제공: Aladin` 출처가 표시되는지 확인한다.

Kakao 또는 Aladin 실제 검색이 성공하면 앱이 MVP 점검의 `도서 API`를 자동 체크한다. 자동 체크가 실패했을 때만 검증 리포트의 `도서 API` 근거를 확인한 뒤 수동 체크한다.

### 5. 음성 메모

1. 캡처 화면의 메모장에서 마이크 버튼을 누른다.
2. 짧은 생각을 말하고 텍스트로 전사되는지 확인한다.
3. 저장 후 책장 상세에서 메모가 남아 있는지 확인한다.

통과하면 MVP 점검의 `음성 메모`를 체크한다.

### 6. LLM 인사이트

1. 인사이트 탭에서 `+`를 눌러 글조각 2-3개를 고른다.
2. `질문`, `연결`, `확장`, `요약` 중 하나를 선택한다.
3. 입력창에 짧은 질문을 넣고 생성한다.
4. 응답이 저장됨 카드로 남고, 선택한 글조각 출처를 다시 볼 수 있는지 확인한다.
5. Anthropic, OpenAI, Gemini 중 하나가 준비된 상태라면 새 글조각 저장 후 자동 태그가 뒤에서 보강되는지 확인한다.

현재 모델 테스트나 실제 생성이 성공하면 앱이 MVP 점검의 `LLM 인사이트`를 자동 체크한다. 자동 체크가 실패했을 때만 검증 리포트의 `LLM 연결` 근거를 확인한 뒤 수동 체크한다.

### 7. 보관함 복구 안전장치

1. 테스트용 책이나 글조각이 있는 상태에서 `책장 > 메뉴 > 보관함 초기화`를 연다.
2. 확인 문구에 복구 백업이 남는다고 안내되는지 확인한다.
3. 초기화 후 책장이 비워졌는지 확인한다.
4. `책장 > 메뉴 > 최근 초기화 복구`를 눌러 직전 상태가 돌아오는지 확인한다.
5. 검증 리포트의 `초기화 복구` 값이 상태에 맞게 표시되는지 확인한다.

이 절차는 MVP 10개 통과 항목에는 포함하지 않지만, 실사용 데이터 손실을 줄이는 안전장치로 실기기에서 1회 확인한다.

## 테스트 세션 저장

1. `책장 > MVP 점검 > 테스트 세션 기록`을 연다.
2. 남은 항목 중 이번 세션에서 실패했거나 재검증이 필요한 항목을 켠다.
3. 세션 메모에 기기, 책, 실패 조건을 짧게 남긴다.
4. `현재 상태 기록`을 누른다.
5. 저장 완료 안내가 `MVP 통과 근거로 저장됨`, `실기기 세션 저장됨`, `빌드 확인용 세션 저장됨` 중 무엇인지 확인한다.
6. `검증 리포트`를 열고 `MVP 판정`, `다음 조치`, `도서 API`, `LLM 연결`을 확인한 뒤 복사한다.

최신 리포트에 `MVP 판정: 통과 가능`, `점검: 10/10`, `실패: 없음`, `미확인: 없음` 상태가 남아야 MVP 통과로 본다. `기능 점검 10/10`만으로는 최종 통과가 아니다.

## 실패 시 확인할 것

| 실패 영역 | 먼저 확인 |
| --- | --- |
| 카메라가 열리지 않음 | iOS 설정의 카메라 권한, 실제 기기 실행 여부 |
| OCR 줄 선택이 어긋남 | 책과 카메라 각도, 화면 비율, 페이지가 너무 휘었는지 |
| 페이지 경계가 안 잡힘 | 배경 대비, 페이지 모서리 노출, 손 그림자 |
| 스냅샷이 이상함 | 저장 직전 페이지가 화면 밖으로 벗어났는지 |
| 프리플라이트 저장소가 대기 | 글조각을 1개 저장한 뒤 검증 리포트를 다시 열어 주 저장소/백업 저장 상태 |
| 최근 초기화 복구가 안 보임 | 보관함 초기화 직전에 책이나 글조각이 실제로 있었는지 |
| 저조도 캡처 실패 | 플래시 권한/기기 지원, 반사광, 초점 |
| ISBN 인식 실패 | 바코드 훼손, 빛 반사, 너무 가까운 거리 |
| 도서 API 키는 준비됐지만 검색 실패 | [BOOK_METADATA_API_KEYS.md](BOOK_METADATA_API_KEYS.md)의 앱 번들 Info.plist 검증 후 `책 추가`에서 ISBN과 제목 검색을 각각 실행 |
| Kakao 검색 실패 | REST 키 오타, 네트워크, 도서가 Kakao DB에 없는 경우 |
| 음성 메모 실패 | 마이크/음성 인식 권한, 온디바이스 인식 지원 언어 |
| LLM 키는 준비됐지만 연결 대기 | `인사이트 > AI 설정 > 현재 모델 테스트`를 다시 실행하고 검증 리포트의 `LLM 연결` 날짜 확인 |
| LLM 실패 | 제공자 API 키, 모델 ID, 네트워크, 잔액/쿼터 |
| 자동 태그가 붙지 않음 | [AUTOMATIC_TAGGING.md](AUTOMATIC_TAGGING.md)의 provider 우선순위, 설정 준비 상태, `CaptureMetrics` 로그 확인 |

## 보류되는 지표

`D7 Retention >= 40%`와 활성 사용자 기준 `LLM 기능 사용률 >= 30%`는 단일 실기기 테스트로 증명할 수 없다. 앱의 `검증 리포트 > MVP 성공 지표`에는 로컬 사용 상태와 함께 `TestFlight 코호트 필요`로 표시된다. MVP 기능 통과 후 TestFlight 소규모 배포에서 코호트 기준으로 검증한다.

## 저작권/개인정보 원칙

- 표지 이미지는 API가 반환한 URL만 참조한다.
- OCR 캡처와 스냅샷은 개인 기기 로컬 저장을 전제로 한다.
- 주 저장소는 SwiftData, 복구용 백업은 이 기기의 UserDefaults와 로컬 파일 시스템에 둔다.
- 캡처 스냅샷과 초기화 복구 스냅샷은 iCloud 백업에서 제외한다.
- 개인정보 매니페스트가 앱 번들에 포함되어야 한다.
- 카메라, 마이크, 음성 인식 권한 문구가 앱 번들에 포함되어야 한다.
- App Intents 메타데이터가 앱 번들에 포함되어 Shortcuts/Siri 진입점이 노출되어야 한다.
- 번들 ID, 앱 버전/build, 앱 아이콘이 앱 번들에 포함되어야 한다.
- v1에서는 클라우드 동기화를 하지 않는다.
- LLM 인사이트는 사용자가 생성 버튼을 누를 때 선택한 글조각과 메모를 전송한다.
- 자동 태그 보강은 AI provider가 설정된 경우 글조각 저장 직후 선택한 글조각, 메모, 책 정보를 전송할 수 있다. 자세한 정책은 [AUTOMATIC_TAGGING.md](AUTOMATIC_TAGGING.md)를 따른다.
- 공유 기능은 매번 확인을 거치며, 책 원문 전문을 공개 채널에 올리지 않는다.
