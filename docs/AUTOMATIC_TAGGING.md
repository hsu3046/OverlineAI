# Automatic Tagging

Overline은 캡처 저장 후 글조각을 다시 찾기 쉽도록 태그를 자동 보강한다. 목표는 저장 속도를 늦추지 않으면서, 사용자가 반복해서 쓰는 주제어를 자연스럽게 재사용하고, 설정된 AI가 있으면 짧은 태그를 추가 제안하는 것이다.

## 동작 원칙

1. 글조각 저장은 먼저 완료한다.
2. 책에 등록된 기본 태그를 즉시 붙인다.
3. 같은 책에서 반복적으로 나온 태그를 다음 캡처의 기본 후보로 재사용한다.
4. 카메라 또는 사진 OCR 캡처는 로컬 OCR 자동 교정을 먼저 마친 뒤 최신 본문으로 태그를 보강한다.
5. 로컬 교정이 필요 없거나 기기에서 지원되지 않아도 태그 보강은 그대로 진행한다.

자동 태그는 캡처 UX를 막지 않는다. AI 호출이 실패해도 저장된 글조각은 그대로 유지된다.

## 발동 시점

아래 저장 경로에서 글조각 저장이 끝난 뒤 자동 태그 생성이 실행된다. 카메라와 사진 OCR 캡처는 로컬 OCR 자동 교정이 완료된 다음 실행해, 교정이 사용자 편집으로 오인되어 태그가 취소되지 않게 한다.

- 카메라/OCR 캡처 저장
- 갤러리 사진 OCR 저장
- 메모만 저장하는 quick thought 저장

사용자가 메모를 나중에 수정하면 기존 저장 로직이 글조각을 amend한다. 카메라에서 `이어 밑줄긋기`로 두 번째 페이지를 붙인 경우에는 합쳐진 전체 본문을 기준으로 자동 태그 보강을 다시 시도한다.

자동 태그 보강이 성공하면 캡처 화면에 `태그 추천됨` 상태를 표시한다. 이 상태에서도 직전 글조각 삭제 버튼은 유지되어야 한다.

## 로컬 태그 재사용

로컬 재사용은 외부 AI를 쓰지 않는다.

- 책 편집 화면에 등록한 태그는 해당 책의 모든 새 글조각 기본 태그가 된다.
- 같은 책 안에서 2회 이상 반복된 태그만 다음 캡처 후보에 추가한다.
- 반복 태그는 많이 나온 순, 최근에 나온 순으로 정렬한다.
- 책 기본 태그와 반복 태그를 합쳐 중복을 제거한다.

한 번만 나온 태그는 기본 후보로 올리지 않는다. 오작동이나 임시 태그가 다음 캡처에 번지는 것을 막기 위함이다.

## AI 태그 보강

AI 태그 보강은 AI 설정에서 현재 선택한 provider, 모델, 인증 방식이 준비된 경우에만 실행한다. 다른 provider의 credential이 함께 저장되어 있어도 자동으로 대체하거나 fallback하지 않는다. 따라서 설정의 `현재 모델 테스트`, 인사이트 생성, 자동 태그, 수동 태그 재생성, OCR 교정은 모두 동일한 연결을 사용한다.

예를 들어 설정에서 OpenAI와 GPT-5.4 mini를 선택했다면 Claude 토큰이 기기에 남아 있어도 Claude를 호출하지 않는다. OpenRouter를 선택한 경우에도 선택한 OpenRouter 모델로 태그를 생성한다.

AI 호출이 `401` 또는 `403`을 반환하면 선택한 인증 또는 모델 접근을 거부 상태로 기록한다. 이후 외부 AI 기능은 호출하지 않으며, 사용자가 AI 설정에서 토큰·API 키 또는 모델을 다시 설정하거나 `현재 모델 테스트`에 성공해야 다시 활성화된다.

AI에는 아래 정보만 보낸다.

- 책 제목
- 저자
- 책 소개
- 선택된 글조각 텍스트
- 글조각 메모
- 이미 붙은 태그

페이지 번호, 저장 날짜, 생성 시각은 태그 생성 근거로 보내지 않는다.

## 프롬프트 규칙

AI에는 `태그` 전용 모드로 요청한다.

- JSON만 반환
- 형식: `{"tags":["태그1","태그2"]}`
- 2-4개 태그
- `#` 기호 금지
- 설명 문장, 마크다운, 머리말 금지
- 짧은 한국어 명사형 우선
- 너무 일반적인 태그 금지: 책, 글, 글조각, 문장, 인용, 메모, 독서, 한국어 등
- 책 정보는 배경으로만 쓰고, 선택된 글조각의 핵심 주제를 우선

앱은 응답을 다시 정규화한다. `#`가 붙어 있으면 제거 후 다시 붙이고, 내부 공백은 제거한다.

## 저장 규칙

- 기존 태그는 유지한다.
- AI가 만든 태그는 기존 태그 뒤에 추가한다.
- 중복 태그는 제거한다.
- 글조각 하나의 태그는 최대 6개까지만 보강한다.
- 사용자가 직접 편집한 기존 태그를 자동 태그가 삭제하거나 덮어쓰지 않는다.
- AI 요청이 진행되는 동안 사용자가 글조각, 메모, 태그, 책 소속을 바꾸면 자동 태그 적용을 건너뛴다.
- 글조각 편집 화면이 열린 상태에서 자동 태그가 먼저 붙고, 사용자가 태그 입력칸을 건드리지 않았다면 편집 저장 시 최신 태그를 보존한다.

## 글조각 편집에서 수동 재생성

글조각 편집 화면의 태그 라벨 오른쪽에는 AI 태그 재생성 버튼이 있다. 자동 태그와 달리 수동 재생성은 현재 태그에 새 태그를 덧붙이지 않고, 해당 글조각에 가장 적합한 최종 태그 묶음 2-4개를 새로 제안한다.

1. 편집 중인 글조각, 메모, 책 정보, 현재 태그를 AI 설정에서 선택한 모델에 보낸다.
2. AI는 글조각 본문을 가장 중요한 근거로 사용하고 현재 태그는 참고만 한다.
3. 새 태그와 현재 태그를 미리보기에서 비교한다.
4. 사용자가 적용 버튼을 눌렀을 때만 편집 중인 태그 입력란을 교체한다.
5. 편집 화면 상단의 완료 버튼을 누르기 전에는 저장소를 변경하지 않는다.

요청 중 본문, 메모, 태그 또는 선택한 책이 바뀌면 응답을 폐기한다. 따라서 늦게 도착한 AI 응답이 사용자의 최신 편집을 덮어쓰지 않는다. 편집 화면을 연 뒤 백그라운드 자동 태그가 먼저 저장된 경우에도, 사용자가 수동 재생성 결과를 적용하지 않았다면 기존 최신 태그 보존 규칙을 그대로 따른다.

## 로그

자동 태그는 `CaptureMetrics` 로그에 provider, model, 결과 개수, 실패 타입만 남긴다.

- `auto_tags_requested`
- `auto_tags_empty`
- `auto_tags_applied`
- `auto_tags_failed`
- `auto_tags_skipped`

API 키, access token, 글조각 전문은 로그에 남기지 않는다.

## 개인정보 원칙

자동 태그 보강은 사용자가 AI provider를 설정한 경우에만 외부 AI로 요청한다. 설정이 없으면 로컬 태그 재사용만 동작한다.

배포 전에는 설정 화면과 개인정보 문구에서 아래를 명확히 해야 한다.

- 글조각 저장 후 태그 추천을 위해 선택한 글조각과 책 정보가 설정된 AI provider로 전송될 수 있다.
- AI provider가 설정되지 않은 경우 외부 전송 없이 로컬 태그만 재사용된다.
- 사용자는 AI 연결을 해제해 자동 태그 보강을 멈출 수 있어야 한다.
