# 보관함 백업

## 범위

사용자는 설정의 보관함 섹션에서 책, 글조각, 독서 기록과 인사이트를 하나의 `.bzogak` 파일로 내보내거나 다시 가져올 수 있다.

백업에는 다음 항목을 포함하지 않는다.

- 외부 AI API 키와 전송 동의
- 음성, 낭독 속도 등 앱 설정
- 고품질 음성 팩
- 읽어주기 임시 글
- 처리 후 삭제되는 원본 사진과 음성 녹음

## 파일 형식

백업은 `vote.aib.bzogak.backup` 형식의 JSON 파일이다. 최상위에 형식 식별자, 형식 버전, 생성 시각, 앱 버전과 보관함 스냅샷을 기록한다. 파일 확장자는 `.bzogak`이며 현재 형식 버전은 `1`이다.

내보내기와 가져오기 모두 파일 크기를 50MB(50 × 1,024 × 1,024바이트)로 제한한다. 내보내기는 직렬화된 실제 크기를 검사한 뒤에만 저장 창을 열어, 앱에서 다시 가져올 수 없는 파일을 성공한 백업으로 안내하지 않는다. 한도를 넘으면 현재 보관함을 그대로 유지하고 오류를 표시한다.

가져올 때는 먼저 형식 식별자와 형식 버전만 읽고, 지원하는 버전일 때에만 본문을 해석하고 중복 ID를 검사한다. 새 버전에서 본문 구조가 달라졌더라도 손상된 파일로 오인하지 않고 앱 업데이트를 안내한다.

## 복구 정책

가져오기는 현재 보관함 전체를 선택한 백업으로 교체한다. 교체 전에 현재 보관함이 비어 있지 않으면 기존 상태를 기기 내부의 최근 초기화 복구에 보관한다. API 키와 앱 설정은 가져오기 전 상태를 그대로 유지한다.

## 진행 중인 AI 요청

인사이트 생성은 요청 시작 시점의 보관함 식별값(`contentRevision`)을 기억한다. 가져오기, 초기화, 성공한 복구는 새 식별값을 부여하며, 응답 저장 직전에 실제 보관함 모델이 이를 비교한다. 식별값이 달라졌으면 이전 글조각의 결과를 저장하지 않고 다시 선택하도록 안내한다. 비교와 저장은 MainActor에서 중단 없이 처리한다.

같은 책 ID를 가진 백업을 다시 가져와도 이전 응답은 무효다. 실패한 복구나 일반 저장은 식별값을 바꾸지 않는다. 교체 시 화면의 글조각 선택과 삭제 취소 상태도 해제한다. 진행 중인 네트워크 요청 자체를 취소하는 기능은 아니며, 백업 파일 형식이나 기존 저장 데이터는 바꾸지 않는다.

## 회귀 검증

`bash Tests/LibraryBackupCodec/run.sh`는 macOS와 Xcode의 Swift 도구로 실제 `LibraryBackup.swift`를 컴파일한다. iOS 앱과 저장소 대신 최소 스냅샷 fixture를 연결하여 형식 헤더 우선 검증, 미지원 버전, 손상 파일, 빈 파일, 중복 ID, 기본 왕복 처리, 정확히 50MiB 및 1바이트 초과 경계를 검사한다. 실제 앱 모델의 전체 호환성이나 가져오기 후 저장 동작을 대체하는 테스트는 아니다.

`bash Tests/LibraryContentRevision/run.sh`는 실제 `Models.swift`, `LibraryBackup.swift`, `OCRLineJoiner.swift`를 컴파일하고 AI 응답을 의도적으로 지연시켜 7가지 상태를 검사한다. 변경 없음, 가져오기, 동일 ID 가져오기, 초기화, 성공한 복구, 실패한 복구, 동일 백업 반복 가져오기를 다룬다. 설정 저장소는 메모리로, 이미지 정리는 무동작으로 대체하므로 실제 사용자 기록·파일에는 접근하지 않는다. 네트워크 AI 호출이나 실기기 UI 동작을 검증한 것은 아니다.

2026-09-04 PR #19 리뷰에서 발견된 헤더 검증 순서와 내보내기 크기 제한 누락을 같은 코덱 경계 문제로 수정했다. 모든 내보내기·가져오기 호출은 이 코덱을 통하며, 내부 초기화 복구 스냅샷은 별도의 비공개 저장 형식이므로 변경하지 않았다. 이 수정은 이미 업로드한 Build 4에는 포함되지 않는다.
