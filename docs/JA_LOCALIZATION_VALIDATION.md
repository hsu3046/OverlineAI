# 한국어·일본어 현지화 선행 검증

> 2026-09-25 이후 앱 번역과 제공자 전환의 현재 상태는 [로케일 구현](LOCALIZATION.md)을 참조한다. 아래는 2026-09-15 선행 조사와 당시 검증 결과다.

## TL;DR

2026-09-15: 한국어 유지 → 일본어 지원 → 영어 마지막 순서. 아래 기존 API 검증 후, 사용자 촬영 실패를 재현하고 iOS 26 문서 인식 경로를 적용했다. 앱 전체 번역·도서/지도 공급자 전환은 이번 OCR 수정 범위에 포함하지 않았다.

## 수정 및 재검증

- 원인: 기존 `VNRecognizeTextRequest` revision 3은 제공된 세로쓰기 본문 영역에서 결과 0줄. 언어 지정만 바꾸어도 동일했다.
- 해결: iOS 26 이상에서 `RecognizeDocumentsRequest` 사용. 촬영 정지 프레임, 실시간 인식, 일반 사진 OCR이 공용 `OCRDocumentRecognizer`를 사용한다. 별도 서비스로 이미지 전송은 없다.
- 문서 엔진이 제공하는 읽기 순서와 `textDirection`을 보존한다. 세로줄 좌표에 기존 가로줄 방향 점수 보정을 적용하지 않는다.
- Vision의 세로줄 사각형 꼭짓점은 글줄 기준이므로 화면 기준 꼭짓점으로 변환한다. 세로 하이라이트와 선택 허용 범위는 열 너비를 사용한다.
- 페이지 추정에서 세로열을 포함하며, 문장 조립에서 가로줄 들여쓰기 휴리스틱을 세로열에 적용하지 않는다. 일본어 문장부호/닫는 따옴표 뒤 공백 삽입을 제거했다.
- 인식 중/오류/빈 결과 안내를 분리했다. iOS 26 미만은 기존 인식 경로와 세로쓰기 지원 한계 안내를 유지한다.

### 검증 결과

`bash Tests/OCRDocumentRecognition/run.sh [선택: 개인 스크린샷 경로]`

- 한국어·일본어·영어 가로 합성 샘플: 공백을 포함한 정답 문자열과 일치.
- 일본어 세로 합성 샘플: 3열, 정답 문자열 일치, 오른쪽→왼쪽 순서/세로 방향/화면 기준 꼭짓점 검증.
- 제공 스크린샷: 세로 글줄 13개, 413자 인식. **정답 전사와 비교한 정확도 수치가 아니며, 화면에 잘린 부분은 복원하지 못한다.** 스크린샷/본문은 저장소에 추가하지 않았다.
- 실제 production assembler를 컴파일해 선택 열만 포함, 순서, 중복 제거, 일본어 문장 연결을 검증했다. 세로 선택 함수의 해당 열 선택/옆 열 제외/범위 밖·빈 제스처 제외를 검증했다.
- iOS Simulator Debug 빌드 성공. 실제 iPhone 촬영 및 터치 조작의 종단 검증은 아직 수행하지 않았다.

### 실기기 확인 순서

1. 수정 빌드를 iOS 26 이상 iPhone에 설치한다.
2. 같은 페이지를 촬영하고 ‘모든 글 저장’으로 본문과 열 순서를 확인한다.
3. 다시 촬영해 세로 한 열을 따라 긋고, 옆 열이 선택되지 않는지 확인한다.
4. 네모로 두 열을 선택한 뒤 오른쪽 열부터 저장되는지 확인한다.
5. 한국어 가로 페이지도 촬영해 선택·저장 회귀 오류를 확인한다.

후리가나와 복잡한 혼합 레이아웃의 정확도는 별도 실사진 검증 대상이다.

### 실기기 피드백: 세로로 긋기

사용자는 전체/사각형 인식이 정상 작동함을 확인했다. 다만 세로로 긋기는 시작 단계의 세로 이동 취소 조건과 종료 단계의 가로 폭 조건 때문에 거부되고 있었다. 기존 OCR/열 선택 테스트는 이 제스처 진입 경로를 검사하지 못했다.

- 선 시작 기준을 방향에 관계없이 14pt 이동으로 통일했다.
- 선 완료 기준은 가로/세로 중 긴 축 54pt 및 경로 길이 54pt로 통일했다.
- 캔버스 드래그는 상위 스크롤보다 우선하도록 변경하고, 최초 터치 좌표를 실제 startLocation에서 받는다.
- 상하좌우 시작/완료, 짧은 이동/손떨림 제외 회귀 테스트를 추가했다.
- 후속 실기기 확인: 세로 본문 위를 위→아래/아래→위로 긋기, 한국어 가로 긋기, 사각형 선택, 캔버스 바깥 스크롤.

## 기존 API OCR 실측 (수정 전 기준선)

실행: `bash Tests/OCRLocaleProbe/run.sh /tmp/bzogak-ocr-locale-baseline`

- 환경: macOS 26.3.1 (a), Vision VNRecognizeTextRequest revision 3, accurate, 언어 자동 감지/교정 활성화.
- 앱과 같은 ko-KR/en-US/ja-JP 설정과 각 샘플의 단일 언어 설정을 비교했다.
- 앱의 실제 OCRLineJoiner.swift를 컴파일해 후처리에 사용했다.
- 자체 작성 문장으로 생성한 합성 이미지 4개, 설정별 2회씩 총 8개 관측이다.

| 샘플 | 혼합 언어 | 단일 언어 | 공백 제외 문자 오류율 |
|---|---|---|---|
| 한국어 가로 | 2줄 인식 | 2줄 인식 | 양쪽 0% |
| 일본어 가로 | 2줄 인식 | 2줄 인식 | 양쪽 0% |
| 일본어 세로 | 0줄 인식 | 0줄 인식 | 양쪽 100% |
| 영어 가로 | 2줄 인식 | 2줄 인식 | 양쪽 0% |

문자 오류율은 공백을 제외한 Levenshtein 거리 / 정답 문자 수이다. 일본어 가로 결과의 `。 心`처럼 문장 사이에 공백이 들어가므로 0%는 정확한 최종 문자열 일치를 뜻하지 않는다. 진단 도구는 미인식을 보고서에 기록하며, exit 0은 진단 실행 완료만 의미한다.

원시 결과·좌표·지원 언어·이미지: [검증 결과](validation/ocr-locale-2026-09-15/results.json), [세로 이미지](validation/ocr-locale-2026-09-15/ja-vertical.png).

### 확인된 사실과 아직 모르는 것

- 위 세로 이미지에서 Vision 원시 결과 자체가 비어 있다. 후처리의 줄 정렬만 수정해 해결할 수 없다.
- 일본어 단독 지정만으로 해당 샘플의 미인식은 해소되지 않는다.
- OCRLineJoiner는 일본어 구두점 뒤 공백을 삽입한다.
- CameraTextScanner의 페이지 추정과 좌표 보정 점수에는 가로로 넓은 줄/위→아래 순서 가정이 있다. 카메라에서의 실제 영향은 미검증이다.
- 합성 세로 이미지는 정자 글자를 열 단위로 배치한 통제 샘플이다. 실제 조판, 후리가나, 회전 구두점, 책 곡면·그림자·사진 품질을 재현하지 않는다.
- 이 결과로 모든 일본어 세로쓰기나 iPhone Vision 지원 여부를 단정하지 않는다. OCRTextRecognizer의 UIKit 경로, 실시간 카메라, 선택 UI, 저장, AI 교정도 실행하지 않았다.

1. 동일 이미지와 실제 일본어 책 사진으로 지원 대상 iPhone에서 재현한다.
2. 세로쓰기·후리가나·혼합 레이아웃·곡면을 포함해 정답 전사를 준비한다.
3. 원시 인식, 읽기 순서, 공백/구두점, 선택 영역, 저장 결과를 각각 기록한다.
4. 결과에 따라 인식 엔진/세로 열 처리 대안을 비교한다. 이미지 전체 90도 회전은 글자까지 눕히므로 해결책으로 가정하지 않는다.

## 도서 공급자 비교

| 항목 | Rakuten Books | Google Books |
|---|---|---|
| 검색 | 제목·저자·출판사·ISBN | 제목·저자·ISBN 검색 연산자 |
| 현지화 관련 | 제목/저자 가나, 시리즈 정보 | language, langRestrict |
| 앱에 필요한 필드 | 제목·저자·출판사·ISBN·표지·소개·발매일 | 제목·저자·출판사·식별자·이미지·소개·발행일 |
| 이번 실응답 검증 | 미실행: 확인한 로컬 설정에 App ID/Access Key 없음 | 무키 요청 1회 HTTP 429, 중단 |
| 현 단계 판단 | 일본어 우선 후보, 품질 미확정 | 보완 후보, 품질 미확정 |

Rakuten 최신 문서는 `applicationId`와 `accessKey`를 모두 요구한다. `outOfStockFlag=1`로 품절/판매 종료 항목을 포함할 수 있다. 발매일은 연/월/일 정밀도가 일정하지 않으므로 강제 날짜 변환을 피한다.

Google Books 실패 요청: `q=intitle:吾輩は猫である inauthor:夏目漱石&maxResults=3`. HTTP 429의 정확한 할당량 원인은 이번 조사에서 확인하지 않았다. 검색 품질 0점이나 일본어 미지원으로 해석하지 않는다. 재시도·우회 요청은 하지 않았다.

키 확인 범위는 프로세스 환경 및 루트/CommunityAPI의 .env.local 내 후보 이름뿐이다. 원격 환경에 키가 없다는 뜻은 아니다. 비밀값을 출력하지 않았다.

### 품질 비교 기준

- 일본어 소설·실용서·만화·구간·신간 각 5종, 총 25종의 정답 ISBN/판본을 고정한다.
- ISBN 정확 일치, 제목/저자 검색 상위 5개 내 정답, 표지·소개·출판사 누락률을 각각 측정한다.
- 문고/단행본/전자책·상하권을 별도 판본으로 평가한다.
- ISBN 검색에는 UI 언어로 강제 필터를 걸지 않는다.
- 인증된 양쪽 실응답과 표시/캐시 조건을 검토한 뒤 공급자를 확정한다.

## 후속 현지화 범위

표시 언어, 도서 검색 시장, 사용자의 위치, OCR 대상 언어는 분리한다. 일본어 화면·위젯·권한 안내·AI 응답과 Google Places/Maps 연동은 후속 구현 대상이다. 현재 도서 검색은 서버에서 Aladin/Kakao를 병렬 요청하고 Aladin 결과를 우선한다.
