# Local OCR Autocorrection

Overline은 카메라나 사진에서 글조각을 저장한 뒤 Apple Foundation Models를 이용해 OCR 결과를 기기 안에서 자동 교정한다. 저장과 화면 전환은 먼저 끝내고 교정은 비동기로 실행하므로 캡처 동작을 기다리게 하지 않는다.

## 동작 범위

- 명백한 OCR 오인식
- 띄어쓰기
- 문장부호
- OCR 행 끝에서 생긴 불필요한 줄바꿈

문장을 다시 쓰거나 요약하거나 표현을 다듬지 않는다. 잘린 문장을 추측해서 완성하지 않으며, 숫자와 문장 순서도 바꾸지 않는다.

책 속의 일반적인 문장도 기본 안전 필터에서 오탐될 수 있으므로, Apple이 사용자 제공 텍스트의 변환 작업에 제공하는 `permissiveContentTransformations` 가드레일을 사용한다. 이는 안전 필터를 끄는 설정이 아니며, 생성 결과에는 아래의 앱 자체 안전 검사를 추가로 적용한다.

## 적용 조건

자동 교정은 아래 조건을 모두 만족할 때만 저장된 본문에 적용한다.

1. iOS 26 이상에서 Apple Intelligence와 시스템 언어 모델을 사용할 수 있다.
2. 시스템 모델이 글조각의 언어를 지원한다.
3. 응답의 길이, 문자 차이, 문장부호 변화와 숫자 보존 여부가 엄격한 안전 검사를 통과한다.
4. 교정이 끝날 때까지 사용자가 해당 글조각을 수정하거나 이동하거나 삭제하지 않았다.

하나라도 만족하지 않으면 원문을 그대로 둔다. 실패 알림으로 캡처 흐름을 방해하지 않으며 외부 AI로 자동 전송하지도 않는다. 기존 글조각 편집 화면의 수동 AI 교정은 별도 기능으로 유지한다.

## 이어 밑줄긋기

첫 페이지 자동 교정이 먼저 끝나더라도 `이어 밑줄긋기`를 시작할 때 저장소의 최신 본문을 다시 기준으로 삼는다. 두 번째 페이지를 붙인 뒤에는 합쳐진 전체 본문을 다시 자동 교정한다. 사용자가 중간에 직접 수정한 경우에는 이전 자동 교정 결과를 적용하지 않는다.

## 성능

- 앱 시작이나 카메라 준비 단계에서 Foundation Models를 미리 불러오지 않는다.
- 글조각 저장 후에만 요청한다.
- 여러 요청은 순서대로 처리해 온디바이스 모델 작업이 겹치지 않게 한다.
- 원문이 지나치게 짧거나 3,000자를 넘으면 자동 교정을 건너뛴다.

## 로그

본문은 기록하지 않고 상태와 실패 유형만 기록한다.

- `local_ocr_correction_requested`
- `local_ocr_correction_applied`
- `local_ocr_correction_skipped`
- `local_ocr_correction_failed`
