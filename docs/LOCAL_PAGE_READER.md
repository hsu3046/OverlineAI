# 종이책 페이지 읽어주기

## 범위

`캡처` 탭의 `읽어주기` 모드는 종이책 한 페이지 또는 여러 페이지를 연속 촬영해 기기에서 OCR한 뒤 낭독한다. 촬영할 때는 본문을 임시로 모으기만 하며, 사용자가 `완료`를 누른 시점에 읽기를 시작한다.

## 처리 흐름

1. 기존 `CameraTextScanner`로 현재 페이지의 정지 화면을 만든다.
2. Apple Vision의 정확도 우선 OCR로 한국어, 영어, 일본어 텍스트를 인식한다.
3. 문서 경계가 충분히 신뢰될 때 경계 안의 줄만 사용한다.
4. 페이지 상단 또는 하단의 페이지 번호와 페이지 번호가 붙은 책·챕터 표기를 제외한다.
5. 기존 OCR 문단 조립 규칙으로 본문을 정리한다.
6. Apple Natural Language의 `NLTokenizer`로 본문을 문장 단위로 나눈다.
7. 각 페이지의 OCR 결과를 현재 세션에 순서대로 추가하고 카메라를 계속 유지한다.
8. 사용자가 촬영을 완료하면 설정에서 선택한 로컬 음성으로 `AVSpeechSynthesizer`가 본문을 낭독한다.
9. `willSpeakRangeOfSpeechString` 콜백의 단어 위치를 현재 문장에 매핑해 가사 화면을 갱신한다.

낭독 큐는 최대 10쪽을 유지한다. 촬영 이미지 자체는 한 장씩 OCR한 직후 폐기하며, 본문과 페이지 경계만 현재 화면의 메모리에 둔다. 사용자가 종료할 때 임시 보관을 선택한 경우에만 OCR 본문과 읽던 위치를 7일 동안 기기에 남긴다.

## 낭독 화면

- 첫 페이지를 촬영하기 전에는 카메라를 표시한다.
- 카메라 하단 중앙의 촬영 버튼으로 페이지를 연속 추가하고, 오른쪽 완료 버튼으로 촬영을 끝낸다.
- 촬영 중에는 `N쪽 준비됨`으로 현재까지 인식된 분량을 표시한다.
- 카메라의 전체 정지 화면을 Vision으로 분석하므로 별도의 인식 영역 가이드 선을 표시하지 않는다.
- 완료를 누르면 가사형 문장 화면의 틀을 먼저 표시하고, 다음 화면 갱신에서 문장 목록과 음성 재생을 시작한다. 카메라 정리는 화면 전환 뒤에 처리한다.
- 카메라와 가사 화면은 헤더와 재생 컨트롤 사이의 남은 높이를 모두 사용한다.
- 페이지 경계는 내부 순서 관리에만 사용하고, 읽기 화면에서는 모든 페이지의 문장을 하나의 연속 스크롤로 표시한다.
- 모든 문장을 고정된 글꼴 구조에 유지하며, 현재 문장이 바뀔 때 네이티브 스크롤 위치 추적으로 화면 중앙에 부드럽게 이동한다.
- 현재 문장은 완전한 명도로 표시하고, 앞뒤 문장은 흐리게 표시한다. 글자 확대 애니메이션은 사용하지 않는다.
- 음성 엔진은 보통 단어마다 위치를 알려주지만, UI 상태는 문장이 바뀔 때만 갱신해 불필요한 렌더링을 피한다.
- 하단에는 왼쪽 추가 촬영, 중앙 재생, 오른쪽 설정 버튼을 같은 축에 배치해 재생 위치를 고정한다.
- 설정에서는 한 겹의 선택 컨트롤로 읽기 속도를 고른다. 재생 중 속도를 바꾸면 현재 문장의 처음부터 새 속도로 이어 읽는다.
- 읽기 화면에는 페이지 번호와 페이지 이동 버튼을 표시하지 않는다.
- 하단 왼쪽의 `+` 버튼은 추가 페이지 촬영을 시작한다. 새 본문은 기존 본문의 끝에만 추가한다.
- 문장 목록은 지연 생성되는 `LazyVStack`으로 표시해 여러 페이지를 준비해도 완료 직후 화면 전환을 막지 않는다.
- 추가 촬영을 시작하면 현재 위치에서 낭독을 일시정지한다. 완료 후 기존에 재생 중이었다면 이어서 재생하고, 이미 끝까지 읽었다면 새로 추가된 첫 페이지부터 시작한다.
- 읽어주기 화면의 틀을 먼저 표시하고 카메라 미리보기 연결을 다음 렌더링 시점으로 미뤄 첫 전환의 체감 대기를 줄인다.
- `밑줄긋기`와 `읽어주기` 중 마지막으로 사용한 모드를 기억하고, 캡처 화면에 다시 들어올 때 해당 모드로 복원한다.
- 읽어주기 화면과 카메라는 임시 글 파일 확인을 기다리지 않고 먼저 표시한다.
- 임시 글을 이어 들을 때 문장 분리는 메인 화면 밖에서 처리하고, 준비가 끝난 결과만 화면에 적용한다.
- 읽어주기가 열린 동안에는 밑줄긋기 화면이 공유 카메라 세션을 중지하지 않는다.

## 임시 보관 원칙

- 촬영 이미지와 생성된 음성은 항상 메모리에서만 사용하며 저장하지 않는다.
- 사용자가 `7일간 임시 보관`을 선택한 경우에만 OCR 본문, 페이지 순서, 읽던 문장 위치를 보관한다.
- 임시 보관은 한 건만 지원한다. 새 글을 보관하려면 이전 글을 바꿀지 먼저 확인한다.
- 임시 글은 앱 전용 파일에 저장하고 iCloud 및 기기 백업 대상에서 제외한다.
- 파일은 iPhone이 잠긴 동안 열 수 없도록 보호한다.
- 7일이 지나거나 파일이 손상되면 앱 시작, 포그라운드 복귀 또는 읽어주기 진입 시 자동으로 삭제한다.
- 임시 글을 이어 듣는 중 앱이 백그라운드로 이동하면 읽던 위치만 갱신하며, 기존 만료일은 연장하지 않는다.
- 새로 촬영한 글은 사용자가 보관을 선택하기 전까지 파일로 저장하지 않는다.
- 책장 데이터베이스, 검색 색인, 공유 및 내보내기에는 임시 글을 포함하지 않는다.
- OCR과 낭독에 서버나 LLM을 호출하지 않는다.
- 앱이 백그라운드로 이동하면 진행 중인 촬영과 OCR을 취소하고 낭독을 일시정지한다.
- 메모리 경고가 오면 현재 읽기 화면을 비우되, 이미 임시 보관한 파일은 유지한다.

음성 선택 설정만 기존 `QuoteSpeechPlayer`의 기기 설정을 재사용하며, 읽은 책 내용은 해당 설정에 포함되지 않는다.

## 보관 UX

- 읽던 글이 있을 때 화면을 닫으면 `7일간 임시 보관`, `지금 지우기`, `계속 읽기`를 제공한다.
- 이미 임시 글이 있고 다른 글을 보관하려 하면 `새 글로 바꾸기`, `이전 글 유지`, `계속 읽기`를 제공한다.
- 읽어주기에 다시 들어오면 남은 보관 기간과 함께 `이어서 듣기`, `새로 시작`을 제공한다.
- `새로 시작`은 기존 임시 글을 바로 지우지 않는다. 새 글을 보관할 때만 교체 여부를 묻는다.

## 현재 필터 범위

페이지 가장자리의 다음 형식을 본문에서 제외한다.

- 독립된 페이지 번호: `155`
- 페이지 표기: `p.155`, `155쪽`
- 페이지 번호와 같은 줄의 머리말·꼬리말: `책 제목 155`, `155 챕터 제목`

페이지 번호가 없는 반복 머리말·꼬리말은 한 장만으로 본문과 안전하게 구분하기 어렵기 때문에 자동 삭제하지 않는다. 여러 페이지에서 반복 여부를 확인하는 필터는 별도 품질 개선 대상으로 둔다.

## 실제 기기 검증

1. `캡처 > 읽어주기`에서 여러 페이지를 연속 촬영하고 완료 전에는 재생되지 않는지 확인한다.
2. 완료를 누르면 첫 페이지부터 재생되고 모든 페이지가 하나의 연속 본문처럼 표시되는지 확인한다.
3. 상단, 하단, 중앙 페이지 번호와 책 제목이 붙은 페이지 번호가 낭독되지 않는지 확인한다.
4. 읽기 화면 하단 왼쪽의 `+`로 페이지를 추가하고 기존 본문 끝에 이어지는지 확인한다.
5. 재생 중 추가 촬영한 경우 기존 위치로 돌아와 이어 읽고, 일시정지 상태였다면 그대로 유지되는지 확인한다.
6. 읽기 속도 선택 버튼이 충분한 높이로 표시되고 현재 문장의 처음부터 새 속도로 이어지는지 확인한다.
7. 화면 종료 시 임시 보관을 선택하고 다시 열었을 때 남은 기간과 이어 듣기 선택창이 표시되는지 확인한다.
8. 이어 듣기 후 앱을 백그라운드로 보냈다가 다시 열었을 때 마지막으로 읽던 문장부터 이어지는지 확인한다.
9. 기존 임시 글이 있는 상태에서 새 글을 촬영하고 종료할 때 이전 글 유지와 새 글로 바꾸기가 각각 올바르게 동작하는지 확인한다.
10. `지금 지우기`를 선택한 뒤 다시 열었을 때 임시 글 안내가 표시되지 않는지 확인한다.
11. 새로 촬영한 글을 보관하지 않고 닫았을 때 기존 임시 글이 유지되는지 확인한다.
12. 낭독 중 앱을 백그라운드로 보내 재생이 멈추고 촬영 작업이 취소되는지 확인한다.
