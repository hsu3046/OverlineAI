## 2026-09-04: 절제된 인터랙션

- 현재 메뉴는 기본 글자색을 유지하고 형광펜을 계속 표시한다. 페이지를 열 때 고른 색을 유지하며, 같은 페이지의 헤더와 푸터는 동일한 색을 쓴다. `aria-current`는 HTML에 남겨 JavaScript가 없어도 선택 상태가 보인다.
- 홈의 세 카드에만 4px 들림, 옅은 그림자, 상단 색상 막대의 20% 확장 효과를 넣었다. 크기와 배치는 유지하며 클릭 기능이나 손 모양 커서를 추가하지 않았다.
- 주요 기능 항목의 아이콘은 마우스를 올릴 때 2px만 움직인다. 카드와 아이콘의 호버 모션은 정밀 포인터가 있는 환경에서만 작동한다.
- 홈의 화면 아래 콘텐츠만 처음 진입할 때 420ms 동안 나타난다. `IntersectionObserver`와 Web Animations를 사용하고, 기본 콘텐츠를 숨기지 않아 JavaScript나 해당 API가 없어도 읽을 수 있다. 이미 화면에 있는 내용과 개인정보처리방침 본문은 애니메이션 대상이 아니다.
- 문의 링크의 밑줄 강조와 FAQ의 펼침 효과를 추가했다. FAQ는 네이티브 `details`를 유지하고, `::details-content`와 `interpolate-size`를 지원할 때만 높이를 부드럽게 전환한다. 미지원 환경에서는 기본 열고 닫기와 짧은 등장 효과를 사용한다.
- 닫힌 FAQ 항목에 마우스를 올릴 때마다 플러스가 250ms 동안 같은 방향으로 90도씩 회전한다. 벗어나도 되돌리지 않고 각도를 유지한다. 아이콘은 고정된 28px 영역의 중심에서 회전하며, 열린 항목의 마이너스와 터치·동작 줄이기 환경에서는 회전하지 않는다.
- 동작 줄이기 설정에서는 이동과 애니메이션을 끈다. 이용 중 설정을 바꿔도 진행 중인 스크롤 등장 효과를 즉시 취소한다. 추가 라이브러리는 없다.

## 2026-09-04: 스크롤에 연동하는 네 색 헤더 보더

- 서비스 소개의 네 색 막대가 헤더 하단에 도달하면 같은 위치의 장식용 복제본으로 이어진다. 원래 막대는 공간을 유지해 본문 높이와 스크롤 위치가 바뀌지 않는다.
- 이후 200px 스크롤 구간에서 중앙부터 헤더 전체 폭으로 확장하고, 두께는 8px에서 3px로 줄어든다. 색과 순서는 유지하며 위로 스크롤하면 동일한 경로로 복원한다.
- 스크롤 갱신은 `requestAnimationFrame`으로 합치고, 크기 측정은 화면·콘텐츠 크기가 바뀔 때만 한다. 완전히 확장된 뒤에는 추가 스타일 변경을 생략한다.
- 동작 줄이기 설정에서는 확장 모션 없이 헤더 도착 시 3px 보더로 전환한다. JavaScript가 없으면 기존 막대를 유지하며, 막대가 없는 개인정보처리방침·문의하기 페이지는 변경하지 않는다.

## 2026-09-04: 앱 스크린샷 갤러리

- 주요 기능과 개인정보 섹션 사이에 앱 미리보기를 추가했다. `design-assets/app-store/screenshots/01.png`부터 `06.png`까지의 원본을 변경하지 않고 순서대로 표시한다.
- 원본 비율을 유지하고, 가로 스크롤과 스냅 정렬을 사용한다. 데스크톱에서는 약 세 장과 다음 화면 일부, 모바일에서는 한 장과 다음 화면 일부가 보인다. 자동 재생과 추가 설명, 휴대폰 프레임, 그림자는 없다.
- 목록에는 폭 640px WebP 여섯 장을 미리 불러오고, 확대할 때 해당 화면의 1284px WebP만 불러온다. 확대 화면에서 이전·다음 이동, 좌우 방향키, 닫기와 Esc를 지원하며 닫을 때 원래 스크롤 위치와 포커스를 유지한다.
- 목록용 여섯 장은 합계 412,404바이트이며, 확대용을 포함해 1,281,786바이트다. 원본 PNG 여섯 장은 6,472,249바이트로 그대로 보존했다.
- 기본 링크와 가로 스크롤은 JavaScript 없이도 작동한다. 확대 이미지가 실패하면 목록 이미지를 유지하고 오류를 표시하며, 늦게 도착한 응답이 새 화면을 덮어쓰지 않게 한다.
- 화살표와 닫기는 번들에 설치된 Lucide의 아이콘 경로를 사용했다. 별도 라이브러리를 설치하거나 다운로드하지 않았으며, 라이선스는 `CommunityAPI/LICENSES/Lucide.txt`에 포함했다.

## 2026-09-04: 스크린샷의 간헐적 빈칸 완화

- 증상: Mac Chrome에서 다른 페이지의 메뉴로 홈에 돌아오면 일부 스크린샷이 잠시 비어 보이고, 기다리거나 창 크기를 바꾸면 나타난다.
- 제공된 HAR의 홈 진입 3회에서 목록 이미지 요청 18건은 모두 정상적인 `304` 응답이었다. 요청별 소요 시간은 19~47ms였고, 각 진입 후 여섯 장의 마지막 응답까지 66~102ms였다. 기록된 요청에는 수 초의 네트워크 지연이나 실패가 없었다. HAR는 이미지 디코딩이나 화면 그리기 상태를 기록하지 않으므로 특정 브라우저 결함을 확정하지는 않았다.
- 작은 목록 이미지에만 `loading="eager" decoding="sync"`를 적용했다. 가로 스크롤의 위치에 관계없이 로딩을 시작하고, 이미지 디코딩보다 다른 화면 갱신을 먼저 허용하던 `async` 설정을 해제한다. `sync`는 브라우저에 주는 힌트이며 모든 렌더링 문제의 해결을 보장하지 않는다.
- 여섯 장의 합계는 약 403KiB다. 갤러리까지 스크롤하지 않는 방문자도 이 이미지를 불러오는 비용을 감수하되, 확대용 이미지의 필요 시 로딩은 유지한다. 갤러리 배치, 스냅 정렬, 접근성, 확대 보기와 이미지 파일 자체는 변경하지 않는다.
- 반복 재요청, 캐시 우회, 타이머 기반 강제 화면 갱신, GPU 레이어 강제 생성은 추가하지 않는다. 사용자는 추가 성능 기록 없이 공개 사례에 근거한 최소 범위 완화를 요청했다.
- [Chromium의 과거 유사 보고](https://issues.chromium.org/issues/350944650)는 참고 사례일 뿐 동일 원인이라는 증거가 아니다. 실제 보고 환경은 Chrome 151이며 로컬 자동 테스트 환경은 Chrome 148이다.

## 2026-09-05: 모바일 메뉴와 확대 미리보기

- 모바일에서도 헤더의 로고 옆에 서비스명을 표시한다. 820px 이하에서는 햄버거 버튼으로 공통 메뉴를 열며 App Store 링크는 메뉴 안에 유지한다.
- 메뉴는 화면 전체 높이의 패널 대신 헤더 오른쪽 아래에 폭 240px의 작은 팝업으로 표시한다. 배경은 어둡게 하지 않고, 각 항목의 터치 높이는 44px로 유지한다.
- 메뉴는 비모달 native popover로 표시하고 본문 스크롤을 허용한다. 같은 헤더 버튼, 바깥 영역 탭, Escape로 닫는다. 터치 또는 휠로 본문을 8px 넘게 스크롤하면 닫되, 키보드 포커스로 발생하는 자동 스크롤에는 닫지 않는다. 데스크톱 폭으로 전환하면 닫힌다. JavaScript 또는 Popover API가 없으면 기존 링크를 표시한다.
- 메뉴의 강제 자동 포커스를 제거하고, Safari에서 포인터 조작 후 남는 버튼 테두리는 입력 방식에 따라 제한한다. 키보드 입력 시 포커스 표시는 복원한다. 전체 화면 미리보기의 모달과 스크롤 잠금은 유지한다.
- Chrome 모바일 에뮬레이션에서 터치 스크롤과 닫힘, 키보드 포커스 테두리, 공통 3페이지의 탭 순서, 바깥 탭과 Escape, 데스크톱 전환을 검증했다. 실제 iPhone의 Safari 테두리 해소 여부는 별도 확인이 필요하다.
- 확대 이미지 영역에서 50px 이상 좌우 스와이프하면 이전·다음 이미지로 이동한다. 세로 이동, 여러 손가락, 확대 상태에서는 전환하지 않으며 첫 장·마지막 장을 넘지 않는다. 기존 화살표와 키보드 탐색은 유지한다.
- Chrome 모바일 에뮬레이션에서 실제 터치 이벤트로 양방향 전환을 확인했다. 실제 iPhone Safari 검증은 별도로 필요하다.

### 헤더 서비스명 효과

- 네 가지 글자색으로 옅은 형광펜 밑줄을 순서대로 그리고 사라지게 한다. 글자 크기와 위치는 변하지 않는다.
- 모바일과 데스크톱 모두 탭 세션의 첫 방문에 한 번 재생한다. 데스크톱 마우스 진입과 키보드 포커스 시 다시 재생하며, 진행 중 중복 실행하지 않는다.
- 동작 줄이기 설정에서는 재생하지 않는다. Chrome 데스크톱·모바일 에뮬레이션에서 순차 재생, 종료, 새로고침 시 자동 재생 생략, 동작 줄이기 설정을 확인했다.
