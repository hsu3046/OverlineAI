# Guideline 2.1 심사 대응 준비

기준일: 2026-09-04. 대상: 글조각 서랍, Apple ID `6808131632`, Version 1.0.

## 진행 상태

- 사용자 확인: 실제 iPhone 시연 영상 촬영 완료. 영상 파일과 기기 정보는 아직 이 작업에 전달되지 않음.
- 최신 패치를 반영한 빌드로 재제출하는 방향에 맞춰 [제출용 영문 답변과 PDF](APP_REVIEW_NOTES.md)를 작성함. Build 3를 고정해 유지할 필요는 없음.
- 2026-09-04 11:01 KST에 최신 패치가 포함된 Version 1.0 / Build 4 업로드 성공. App Store Connect 답변 입력·빌드 선택·재제출은 수행하지 않았으며 사용자가 진행한다. 검증 및 업로드 경고는 [출시 점검표](APP_STORE_RELEASE_CHECKLIST.md)에 기록했다.
- 아래 내용은 Build 3를 조사하면서 만든 배경 분석과 참고용 점검표다. 완료된 영상이나 기존 기능 테스트를 다시 처음부터 진행하라는 지시가 아니다.

## 결론과 범위

이번 메시지의 명시적 사유는 심사 이력이 적은 신규 개발자 앱에 대한 추가 정보 요청이다. 특정 충돌, 계정 삭제 누락, 결제 위반이 실제로 발견됐다는 통보는 아니다. 메시지 아래의 일반적인 예방 지침을 개별 리젝트 사유로 해석하지 않는다.

우선 기존 실기기 테스트·서비스 연동 확인 내역을 활용해 6개 답변을 정리하고, 새로 요구된 실기기 시연 영상을 준비한다. 이미 완료한 확인을 전부 반복하거나 API 승인을 새로 신청하라는 뜻이 아니다. 메타데이터 문제라면 같은 빌드를 다시 제출할 수 있다는 Apple 안내가 있다. 다만 이 메시지만으로 앱의 다른 요건 충족이나 승인 가능성을 보장할 수는 없다. [Apple의 답변·재제출 안내](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/reply-to-app-review-messages/)

| 방향 | 장점 | 조건·단점 |
| --- | --- | --- |
| A. 기존 Build 3의 자료 보완 우선 | 제출한 동작 그대로 설명하고 불필요한 재빌드를 피함 | 실제 QA 통과, AI 접근 방법과 권리 증빙 필요. 외부 UGC 요건 적용 여부는 미확정 |
| B. 필요한 기능을 수정한 새 빌드 | 확인된 결함이나 심사 요구를 제품에서 해결 | 새 번호로 업로드하고 실기기 재검증·영상 재촬영 필요 |

초기에는 A를 제안했지만 이후 최신 패치를 반영한 재제출 방향으로 정리했다. 영상에 나온 앱과 실제 제출할 앱의 동작을 맞춘다. 심사에만 다르게 동작하는 숨김 모드나 임시 원격 기능 차단은 사용하지 않는다.

## 현재 확인한 것

- 초기 리젝트 분석의 기준 소스는 제출 커밋 `742c185`였다. 최신 작업 브랜치 `9fd9aca`의 백업 내보내기, 설정 UI, ONNX 재서명 등의 후속 변경을 포함해 `1.0 (4)`로 빌드·업로드했다. 촬영한 동작과 최종 제출할 앱을 맞춰야 한다. TestFlight는 이를 구분하는 방법 중 하나이지 촬영 자체의 필수 조건은 아니다.
- 기존 심사 메모에는 핵심 경로가 있었지만 실기기 영상·QA 증빙, 대상 이용자, 지역별 차이, 전체 서비스 목록과 권리 자료가 충분히 정리되지 않았다. 이 로컬 문서가 실제 제출된 Notes와 같았는지는 별도 확인이 필요하다.
- 앱 계정·유료 기능은 없다. 외부 AI의 제공자 계정/API 키는 별개이며 인사이트 등 해당 기능을 직접 심사하려면 접근 준비가 필요하다.
- 책 삭제는 이미 책 편집 화면 하단에 있다. 발견성과 삭제 범위 안내 개선은 별도 이슈로 보류하며, 이번 답변에서 미구현 기능을 구현된 것처럼 설명하지 않는다.
- 대화에서 사용자가 기능 테스트와 서비스 연동 성공을 확인한 내역이 있다. 이는 그대로 활용한다. 다만 정확한 기종·OS·제출 빌드와 연결된 QA 기록, 실제 App Store Connect 입력 내용, 계정별 API 승인 자료는 이 소스 조사만으로 확인한 것으로 표시하지 않는다. 기록을 찾지 못한 것과 실제 작업이 미완료인 것은 구분한다.

## 기존 자료 대조와 추가 자료

아래 표는 모든 작업이 미완료라는 목록이 아니다. 기존 테스트 결과·등록 자료·적용 약관을 먼저 연결하고, 빠진 증빙이나 실제 문제가 확인된 항목만 추가로 처리한다. 최신 공개 OS 실기기 시연 영상은 이번 심사 메시지에서 명시적으로 요구된 자료다.

| 항목 | 확인된 사실 | 다음 조치 |
| --- | --- | --- |
| 실기기 영상 | 사용자 촬영 완료 확인. 파일 자체는 아직 전달되지 않음 | 완성한 영상을 첨부하고 기종·OS·최종 제출 빌드를 연결. 미확인 세부 사항을 대신 진술하지 않음 |
| AI 심사 접근 | 사용자 제공 API 키 필요. 자체 앱 로그인은 없음 | 제공자 약관이 허용하는 심사용 접근 방법 확정. 전용 제한 키를 허용하는 경우 모델·사용량·비용을 제한하고 App Store Connect 비공개 심사 정보로만 전달. 허용 여부 불명확하면 제공자/Apple에 확인 |
| 외부 블로그 UGC | 제목·요약·일부 썸네일 표시. 신고·차단 UI 없음 | 읽기 전용이라는 이유만으로 면제를 단정하지 않기. 현재 동작을 정직하게 설명하고 적용 범위를 확인하거나 새 빌드에서 신고·콘텐츠 숨김·작성자 차단 및 실제 처리 절차를 설계 |
| 제공자 권한 | 기존 API 연동 성공 내역과 공식 API 호출 경로가 있음 | 이미 받은 등록·승인 내역과 적용 약관을 활용해 이용 범위를 설명. 재발급·재신청을 전제로 하지 않으며 확인되지 않은 권리만 단정하지 않기 |
| 도서관 대출 순위 | 서버 코드에 `DATA4LIBRARY_AUTH_KEY`가 없으면 503을 반환 | 현재 발급·설정·정상 응답을 운영자가 확인. 미설정이면 완료된 기능이라고 제출하지 않고 해결 또는 새 빌드에서 기능 정리 |
| 음성 모델 라이선스 | Supertonic 3 OpenRAIL-M, 모델과 함께 LICENSE 다운로드 | 원문에 있는 사용 제한·후속 이용자 고지 의무가 앱 이용 조건에 적절히 반영됐는지 확인. LICENSE를 내려받는 것만으로 전체 의무 충족을 단정하지 않기 |

Apple의 1.2는 외부 웹 서비스 UGC도 다루므로 “글쓰기 기능 없음”과 “UGC 없음”은 다르다. 이메일 문의만으로 신고·차단 요건을 모두 충족한다고 쓰지 않는다. 5.2.2는 외부 콘텐츠 사용이 해당 서비스 약관상 허용되어야 하며 요청 시 권한 자료를 제출하도록 한다. [App Review Guidelines 1.2 / 5.2.2](https://developer.apple.com/app-store/review/guidelines/)

AI 영상은 접근 방법을 설명하는 보조 자료다. 심사자의 직접 테스트를 대체한다고 단정하지 않는다. 키를 생성하거나 비용을 지출하거나 공유하기 전 소유자 승인을 받고, 비밀값을 Git·문서·영상·공개 링크에 넣지 않는다. 심사 기간에는 접근이 유효해야 하며 심사 종료 후 폐기한다.

API 서버가 정상 응답한다는 사실만으로 모든 제공자가 정상인 것은 아니다. `/api/v1/health`는 단순 상태 응답이며 제공자 연결을 검사하지 않는다. 실제 앱에서 책 검색, NAVER·Daum 각각, 판매 순위·대출 순위 각각, 주변 장소를 점검한다. 운영 서버 비밀값을 읽거나 출력할 필요는 없다.

권리 증빙은 별도 비공개 첨부로 준비한다. 개발자 앱 등록 화면, 승인 내역, 적용 약관과 이용 범위, 라이선스 링크를 제공자별로 연결하고 키·불필요한 계정 정보는 가린다. 블로그·표지 원저작자 권리를 모두 소유한다고 진술하지 않는다. 캡처/공유의 적법성이 책 소유나 개인 용도만으로 모든 국가에서 보장된다고 표현하지 않는다.

## 영상 촬영 순서 (참고)

촬영은 이미 완료됐다. 아래는 기존에 제공한 참고 순서이며 추가 촬영을 요청하는 것이 아니다.

목표 길이는 3~5분 정도로 제안하며 Apple이 정한 길이 제한이라는 뜻은 아니다. 핵심은 실행부터 실제 사용까지 보여주는 것이다. 홍보 영상, 시뮬레이터 화면이나 합성된 화면으로 대체하지 않는다.

1. 실제 iPhone과 설치된 iOS 버전을 기록하고 촬영할 앱이 재제출할 앱과 같은 동작인지 확인한다. TestFlight는 제출용 앱을 확인하는 방법 중 하나다. 기존 데이터가 있는 앱을 삭제하거나 보관함을 초기화하지 않는다.
2. 앱이 닫혀 있는 홈 화면에서 녹화를 시작하고 앱 아이콘을 눌러 실행한다. 알림에 개인정보가 나타나지 않게 준비한다. 계정 가입이나 로그인 단계가 없음을 보여준다.
3. 책장 > +에서 `심사용 독서 노트`를 수동 등록한다. 제목 입력 후 체크 표시로 저장한다. 검색 없이도 사용할 수 있음을 보여준다.
4. 캡처 > 밑줄긋기에서 이 책을 선택한다. 아래 예시를 종이에 출력해 촬영하고 문장을 손가락으로 선택한다. 메모 `이 문장을 다시 읽고 싶어요.`를 남긴 뒤 책장에서 저장 결과를 연다.
5. 책 상세의 독서 기록 +에서 날짜·별점·짧은 감상을 저장한다. 삭제 확인을 보여주려면 방금 만든 **시연용 데이터만** 대상으로 하고 실제 기록은 건드리지 않는다. 계정 삭제 흐름은 없으므로 만들거나 가장하지 않는다.
6. 읽어주기로 같은 페이지를 촬영하고 완료한다. 자동 재생되지 않는 상태와 Play를 눌러 낭독이 시작되는 모습을 보여준다. 홈 화면으로 나가 계속 재생되는지 확인하고 돌아온다. 화면 잠금으로 녹화가 끊기면 잠금 재생은 별도 실기기 촬영/테스트 기록으로 보완한다.
7. 외부 AI는 심사용 접근을 먼저 준비한다. 키 입력·복사 장면 없이, 설정의 제공자·모델·동의 상태와 인사이트에서 글조각 선택 > 질문 > 결과 > 저장을 보여준다. 예시 질문: `선택한 문장의 공통 주제를 두 문장으로 정리해 주세요.` 영상에 키가 노출되면 해당 키를 폐기하고 다시 촬영한다.
8. 커뮤니티에서 인기 도서, 관련 글 검색과 원문 외부 열기, 내 주변의 위치 권한과 결과를 보여준다. 외부 UGC라는 점과 현재 제공하지 않는 신고·차단을 숨기지 않는다. 검색 결과를 읽기 전용으로 보는 동작과 개인 메모를 구분한다.
9. 설정에서 개인정보 처리방침, 이용 조건, 오픈소스 라이선스 접근을 보여주고 마친다. 영상 파일명, 기종, OS, 빌드, 날짜를 심사 메모와 일치시킨다.

음성은 녹화 파일을 실제로 재생해 들리는지 확인한다. 고품질 음성팩은 사용자 확인 후 미리 받아 둘 수 있지만, 사용한 음성 방식과 다운로드 조건을 설명한다. 계정·결제·앱 내 게시/댓글 기능이 없다는 것을 명시하되, 존재하지 않는 장면을 위해 기능을 새로 만들지 않는다.

### 촬영용 예시 문장

이 심사 준비를 위해 만든 예시다. 출판된 책의 본문이나 실제 사용자 기록 대신 사용한다. 앱으로 파일을 가져오는 것이 아니라 종이에 출력해 카메라로 인식한다.

```text
심사용 독서 노트

책을 펼치면 하루의 속도가 조금 느려집니다.
서둘러 지나쳤던 생각들이 문장 사이에서 모습을 드러냅니다.
나는 오늘 마음에 남은 한 문장을 작은 기록으로 남겼습니다.

기록은 모든 내용을 기억하기 위한 일이 아닙니다.
다시 만나고 싶은 생각에 조용히 표시를 남기는 일입니다.
한 줄의 메모가 다음 독서의 출발점이 되기도 합니다.

책을 덮은 뒤에도 질문은 남아 있습니다.
어제의 나와 오늘의 내가 같은 문장을 다르게 읽는 이유는 무엇일까요.
쌓여 가는 글조각을 보며 나의 생각이 바뀌는 과정을 살펴봅니다.
```

## 실제 QA 기록

기존에 실행한 테스트 결과를 이 표로 옮기고, 제출 빌드와 대응하지 않거나 문제가 있는 항목만 필요한 범위에서 재확인한다. 아래의 `기록 연결 전`은 테스트를 한 적이 없다는 뜻이 아니라 이 문서에 아직 구체 증빙이 연결되지 않았다는 뜻이다. iPhone 전용 앱이며 iOS 17 이상을 대상으로 하므로, 최신 OS 실제 기기 영상 외에 기존 QA의 기기·OS 범위를 남긴다. 실제로 테스트하지 않은 모델까지 확인했다고 쓰지 않는다.

| 항목 | 결과 | 기기·OS·날짜 / 증빙 |
| --- | --- | --- |
| 최종 제출 빌드 설치·실행 | 기록 연결 전 | |
| 수동 책 추가, 캡처, 문장 선택, 메모 저장·재실행 후 유지 | 기록 연결 전 | |
| 읽어주기 수동 재생·앱 전환·잠금 재생 | 기록 연결 전 | |

## App Store Connect 제출 순서

1. 영상·QA 결과·AI 접근 방법·권리 자료·대출 순위 상태를 확정한다. 공개 영상 링크를 사용한다면 비로그인 상태에서 재생과 음성을 확인한다. 민감한 증빙은 공개 호스팅하지 않는다.
2. [제출용 영문 답변과 PDF](APP_REVIEW_NOTES.md)를 사용한다. 영상·기기 정보를 추가할 때는 실제 확인한 값만 사용한다. 공개 저장소의 문서에는 API 키를 쓰지 않는다.
3. App Review에서 해당 메시지에 답변하고 영상·증빙을 첨부한다. 같은 내용을 App Review Information > Notes에도 기록한다. 메시지 답변만 하고 Notes를 빠뜨리지 않는다.
4. 앱 설명에 커뮤니티에 직접 생각을 게시하거나 이용자끼리 나누는 기능이 있는 것처럼 쓰여 있다면, `인기 도서와 관련 블로그 글, 가까운 서점과 도서관을 찾아보세요.`처럼 실제 동작으로 수정한다. 현재 App Store의 실제 문구는 사용자가 대조한다.
5. 실제 동작·노출 콘텐츠를 기준으로 연령 등급과 콘텐츠 권한 답변을 다시 확인한다. 외부 검색이라고 모든 유해 콘텐츠 빈도를 자동으로 `없음`에 두지 않는다.
6. 해결한 내용과 App Store Connect의 상태에 따라 같은 빌드로 재제출하거나 Apple의 추가 답변을 따른다. 앱 동작을 고쳤다면 새 빌드 번호·재검증·영상 갱신을 거쳐 제출한다.
